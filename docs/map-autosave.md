# 地图自动保存与云端同步

2026-09-14，用户要求地图编辑实时自动保存，并包含提交服务器。

## 保存范围

- 放置棋子、信息栏改名/移动/删除、移动模式拖放及当前位置；保存 4763×3185 地图逻辑坐标与稳定 ID。空地图也保存，不会刷新后重新生成已删除棋子。
- 每次已确认修改立即写本机；登录现有书房账号后约 1 秒提交 Supabase。进入、回到页面、联网恢复及前台每 15 秒核对云端。刷新后仍以当前位置居中。
- 未登录时本机保存；不同账号与游客存档隔离。`?showcase=1` 演示不读写正式存档。没有修改的默认地图不会覆盖已有云端地图。
- 取消编辑、取消移动、取消删除或 pointercancel 不落盘。当前未提交编辑完成前不自动替换云端地图。
- 本机缓存前缀 `dndcard-map-v1:`，不修改角色卡键、完整角色快照或角色云存档接口。

## 云端协议

独立表 `map_saves`、`map_save_history`，主键 `(user_id,map_id)`；沿用现有认证与本人私有权限，开启 RLS。`save_map` RPC 使用期望 revision 原子更新，每次更新保留前一版本；不同设备旧版本提交产生冲突，保留本机/云端两份，由用户选择，禁止无版本 upsert。

服务器检查地图版本、棋子类型、ID、名称、原图坐标范围、最多一个当前位置与最多 2000 枚棋子。前端只使用既有公开 publishable key，并在每个请求前检查 session 身份，捕获该账号令牌，避免账号切换使进行中的上传指向另一个账号。

服务端迁移 `20260914135148_create_private_map_sync.sql` 与线上迁移版本对应。使用 CLI 创建迁移文件，MCP 部署后按实际迁移历史版本归档。没有执行任何角色存档写入或权限模型变更。

## 状态及恢复

页脚显示本机保存、等待上传、正在同步、云端已同步、冲突或保存失败。只有服务器确认并回读一致后显示云端已同步。断网保留 dirty 快照，下一次登录/联网继续上传；保存配额不足会显式提示不要关闭页面，并允许下载当前地图。

状态面板可以重试、下载当前地图和本账号冲突备份。Web Locks 限制同源地图同时编辑；不支持 Web Locks 时以缓存读前比较阻止旧标签页覆盖。存档损坏不默默重置，保留原始值并阻止继续编辑。

已有旧版地图没有保存代码；已经刷掉的棋子无法恢复。本次检查当前线上旧页仅有默认当前位置，未刷新用户正在摆放的棋子。

## 验证

- 22 项地图测试通过，包括真实 DOM 放置、改名、两种移动、删除及取消、刷新与当前位置居中；模拟云端覆盖断网恢复、双设备冲突、账号切换、请求中继续编辑、丢失回执、存储异常与演示隔离。
- `scripts/verify-map-sync.sql` 在线上事务内创建随机测试身份，验证保存/回读、revision、历史、冲突、输入校验、空地图、双账号 RLS、匿名拒绝，最后回滚。没有写入玩家地图测试记录。
- 本地浏览器实际放置并改名后立即刷新，棋子名称恢复；保存面板视觉检查通过。真实玩家账号跨设备登录不等同于上述模拟验收。
- 安全检查未报告新增地图表/函数问题。另有既有 Auth 配置提示：未开启[泄露密码保护](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)，本次未改变登录配置。
