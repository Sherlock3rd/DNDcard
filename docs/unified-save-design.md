# 单人冒险档案：统一存档与 Git 自动回传

状态：2026-09-15 用户确认以现有邮箱存档为准，公开回传现有 Git 仓库。实施版本使用统一档案入口与 GitHub Actions 自动备份。

## 使用目标

只有一个主人、一份持续更新的冒险档案。每次访问默认恢复最后成功保存的内容；修改自动保存，不再要求挑选角色、地图、日志各自的导入来源，也不再下载 JSON 后手动上传 Git。账号只负责确认谁可以修改这份档案。

## 已核对的现状

- 当前 Supabase 只有一个账号，其下已有角色、地图、日志三种存档；统一档案保持三部分快照和各自版本。
- 实施时重新读取：角色 revision 3，地图 revision 19，日志 revision 1；完整档案初始 revision 1。三个版本号属于不同序列，不能相互比较大小。
- 角色最新云端内容和 9 月 14 日 Git 备份抽查一致：4 级，HP 26，10 项背包，16 项法术书，二环法术位 0，剑歌未开启。
- 现有 Git 导入地址仍写死为 9 月 13 日备份；该旧备份二环法术位为 2、剑歌开启。导出时间不是最后编辑时间，初次整合不能只凭文件名新旧决定覆盖。
- 旧 Git 功能仅下载 JSON 并打开上传页面，没有自动提交，也不覆盖其他设备的基础存档。
- 人物关系网、人物原始背景、地图底图/路网/地名和插画目前属于已发布的代码与静态素材；没有独立的浏览器可编辑关系网存档。不能声称它们已有运行时编辑同步。
- `Sherlock3rd/DNDcard` 当前是公开仓库。用户已明确同意完整游戏存档公开可读，写入仅允许当前主人账号。

## 一份档案的内容

| 部分 | 保存内容 | 保存责任 |
| --- | --- | --- |
| 角色 | 等级、属性、生命、状态、法术位、专长、升级记录、法术书与准备列表 | 延续完整 manager/state，不改变 5e 规则 |
| 装备与资料 | 钱袋、背包数量、装备状态、备注、自定义法术/物品及资料覆盖 | 包含在角色快照，保留未知兼容字段 |
| 地图 | 所有棋子、种类、名称、位置、当前位置、已有地图快照字段 | 沿用稳定棋子 ID |
| 日志 | 日期、全文、原始团录、插画引用、地点、地点坐标、棋子绑定 | 沿用稳定章节和地点 ID |
| 已发布内容 | 人物关系网、人物背景、地图地理数据、底图和插画 | 代码版本及素材引用随 Git 保留，不将大图重复塞进每次 JSON |

账号邮箱、密码、登录令牌、浏览器认证缓存不进入游戏存档。编辑页面只提交自身负责部分，不能从缺少其他页面数据的浏览器缓存拼出空值并覆盖完整档案。

## 存储与读取

对用户只呈现一个“冒险档案”与一个保存状态；内部保留各部分的版本，避免角色页和地图页互相覆盖。

建议 Git 固定入口为 `data/save/latest.json`，由服务端从已确认的完整数据生成。结构包含格式版本、服务端档案版本、各部分版本、更新时间、角色、地图、日志与素材版本。Git 自身的提交历史保存旧版，不再堆积需要手动选择的文件。

打开页面：先呈现最近可用内容，再检查服务端的新版本；首次设备自动读取完整基础存档。仅当最新数据已成功校验、应用后才开放对应编辑，避免默认值抢先上传。常规情况下无导入确认弹窗。离线时显示缓存时间，不能称为最新云端数据。

修改：立即写入本机恢复副本，短暂合并连续操作后上传服务端；服务端按已读版本接受变更并保留历史，再通过持久任务自动生成 Git 快照。关闭网页不取消服务端已接收的回传任务。Git 返回提交 SHA 并回读确认后，才能显示 Git 已备份。

Git 回传失败应重试并显示“云端已保存，Git 备份待完成”，不把两者合成虚假的成功状态。重复内容不提交；并发 Git 写入串行化并检查文件 SHA；旧任务不得覆盖较新档案。页面恢复焦点时检查版本，不依赖 GitHub Pages 构建完成才跨设备同步。

两台设备修改不同部分可以各自保存。两台设备离线修改同一字段时，保留双方副本并提供差异处理；不能通过“最后上传者覆盖全部”丢掉更早但仍有效的内容。正常打开自动读取最新，只有真正冲突时才打断。

## 账号简化

沿用已存在的唯一账号，移除面向多个新用户的注册/选档主流程。可信设备保持登录，新设备首次编辑验证主人身份。不得把 Git 写入密钥放入前端，也不得为免登录而开放匿名写入。

已确认采用公开基础存档：`data/save/latest.json` 位于现有仓库。公开读 API `adventure_archive` 只包含游戏内容；原始角色、地图、日志表与历史仍保持本人访问，并新增唯一主人写入限制。账户密码、邮箱和令牌不导出。

`archive-client.js` 取代三个页面各自的账号面板。首次转换先保存页面现有内容的恢复副本，再采用邮箱最新云端内容；已有旧缓存和历史不删除。匿名浏览者也可看最新，未登录编辑仅留本机，主人登录后按版本上传。原有旧版同步脚本继续保留兼容测试，正式入口不再加载它们。

`.github/workflows/adventure-save.yml` 按约五分钟一批读取完整档案，由该仓库专用、短期 `GITHUB_TOKEN` 更新固定 JSON 文件；没有前端 Git 密钥，也未复制本机 GitHub CLI 的广权限令牌。任务串行化，冲突重读双方，写后按提交 SHA 回读；相同版本不重复提交。云端提交与完整档案更新在同一个数据库事务中完成。

GitHub 排队可能使备份延后，不能承诺五分钟内完成；公共仓库长时间无活动时计划任务可能被 GitHub 停用，可在 Actions 页面重新启用。界面分别显示实时保存版本与 Git 已备份版本。Actions 提交不会自动触发 Pages 构建，因此读取服务端最新档案，网络异常时回退 Git 原始文件再回退发布包，禁止旧备份覆盖更高版本缓存。

## 初次迁移与验收

1. 重读唯一账号的三个服务器快照、Git 最新备份，以及当前设备存在的未上传变更；生成只读差异与完整恢复备份。
2. 以核对后的各部分最新版本组成档案；不自动采用旧默认角色或空地图。旧缓存与服务器历史保留。
3. 接入统一读取、自动保存和 Git 任务；首次写入后回读完整内容并核对版本。
4. 验证全新设备打开、角色装备与法术消耗、地图移动/改名、日志修改与绑定地点均可刷新恢复。
5. 验证跨设备不同模块连续编辑、同模块冲突、离线关闭后恢复、上传中继续编辑、Git 失败重试、旧任务乱序和未授权写入拒绝。
6. 发布后实际确认 Git 固定存档文件与云端相符，再说明完成。不能用只有本机下载的 JSON 代替自动回传验收。

参考：[GitHub 内容写入接口](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)、[Supabase Edge Functions](https://supabase.com/docs/guides/functions)。

## 插画切换优化

原五张 PNG 共 15,156,694 字节；WebP 质量 86、保持 1536×1024，共 1,772,800 字节，减少 88.3%。原始 PNG 保留。渲染时将五张已知原素材路径映射到 WebP，兼容已有日志存档，不修改用户保存的图片字段。

预载相邻章节，先解码再展示；文字立即翻页、图像有加载/失败重试提示，序列号丢弃旧章迟到响应。自定义配图地址仍按原样显示，不擅自替换用户素材。
