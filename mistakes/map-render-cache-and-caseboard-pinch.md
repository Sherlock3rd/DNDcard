# 地图内存缓存与案件板移动手势不能代替持久化和双指交互

2026-10-11：用户反馈地图桌每次进入都从头加载，案件板在移动端不能正常缩放。

## 原因

- 地图分块只保存在页面内的 48 项内存 LRU，`pagehide` 会主动释放；再次进入仍需重新读取区域数据并重绘所有可见分块。
- 案件板设置了 `touch-action:none`，却只实现单指拖动、滚轮和按钮缩放；第二根触点没有手势状态，会与原拖动状态竞争。

## 修复

- 地图 overview 与绘制完成的分块以 PNG Blob 写入 IndexedDB，使用地形、地标和源标记的内容签名作为键前缀；素材变化自动形成新键，LRU 上限 96 项，IndexedDB 不可用或失败时继续使用原内存缓存和实时绘制。
- 案件板跟踪触点，第二根手指加入时取消并回滚未完成的单指拖动；双指距离控制缩放、中心移动控制平移，手势不写案件板存档。

## 防复发

- 地图性能验收必须包含同一浏览器首次进入与刷新后的 `miss -> hit`，不能只检查页面内存缓存。
- 移动端缩放必须同时覆盖 Pointer Events 与原生 Touch Events；飞书内置浏览器或部分移动 Safari 不能只用桌面 Chrome 的 Pointer Events 模拟代替。
- 双触点验收必须按真实顺序先落一指、再落第二指，检查变换、横向溢出、运行时异常和零存档写入。
- 缓存键必须覆盖全部视觉输入，容量必须有明确上限；缓存故障不得让地图退化为不可用。

## 2026-10-11 实机反馈补充

- 首次发布后，桌面 Chrome 触控模拟通过，但用户在真实移动端仍无法缩放。
- 原因是首版仅监听 Pointer Events；飞书内置浏览器 / 部分移动 Safari 会交付原生 Touch Events，案件板没有对应手势路径。
- 修复为触屏端优先使用 `touchstart` / `touchmove` / `touchend` / `touchcancel`，鼠标和支持 Pointer Events 的设备保留原路径；两条路径共享相机数学与拖动收尾逻辑。
