# 房间主页的交互图层

## 现象与原因

先生成完整房间画面再覆盖按钮，会把可交互物品固化在背景中，无法单独改变位置、遮挡和识别反馈。用户要求改为独立物件图层。部分带棋盘格的生成图实际为 RGB，并非透明素材。

## 修正

- 背景只保留建筑与照明；案板、地图桌、书架、人物和日记各自为独立 PNG 与按钮。
- 物品名称由独立 HTML 标签输出；hover 与键盘 focus 单独作用于物品。
- 验证 PNG 真实 alpha，不能以视觉棋盘格判定透明。
- 手机竖屏保留横向探索及导览；横屏检查底部导览不能被最小高度截断。

## 复用检查

开始交互场景设计前先定义图层、点击目标和标签；测试物品入口、关闭返回、键盘可达性、移动布局及导航不写玩家存档。

## 2026-09-14：纠正独立生成替代原图拆分

上一版把“独立透明 PNG”错误当成“从原画拆层”。分别生成的物件与房间视角、比例、光源和阴影不一致；仅验证 alpha 和交互功能不足以验收。用户明确要求按原图重做。

修正：使用用户原图做确定性像素分区，六张同画布 PNG 重构原图，禁止单独重新绘制物件和额外 CSS 阴影。保留原画可见遮挡关系。验收新增原图 hash、逐像素重构以及浏览器缩放差异图。图层独立不代表可任意移动：原图遮挡后方未绘制区域不应假装存在。
